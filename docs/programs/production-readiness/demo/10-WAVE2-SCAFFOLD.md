# Wave 2 scaffold

Audience: INTERNAL_RESTRICTED

Status: `NOT_AUTHORIZED`

This file records the implementation shape a later force would need. It does not open that force, does not change `packages/vantio-cli`, and does not add a package script.

## Preconditions a later force must show before writing code

1. A council disposition on this directory that is not the producer classification.
2. Founder beat text in the tree, or an explicit decision to keep B01–B18 as the room sequence.
3. A writable-path grant that names the CLI files. This force's writable path does not include them.
4. CLI version policy. 0.3.24 is frozen in the current product boundary. A labeled demo writer is a future CLI version, not a silent edit of 0.3.24.

## Behavior that scaffold is aimed at

1. `demo` persists `evidence_origin` `SIMULATED_DEMO` and `producer` `demo_command` with a producer version string that matches the architecture charset rule.
2. The demo writer still uses hostname `optics-demo.invalid`, `network` none, `content` null, and action `OBSERVED` only as the stored call action. It still does not write `LOCAL_OBSERVATION`.
3. Human output keeps the sentence `Demo — in-process stub. No network.`
4. `prove` and `discover` for that origin print the simulation label and exclude the row from any sentence that says customer or observed-locally totals.
5. Trace id and timestamp for a demo profile can be fixed by an explicit demo flag so a room can match `06-EXPECTED-OUTPUTS.md` byte for byte. The default UUID behavior can remain for ordinary use. This force does not choose the flag name.
6. An executable reset accepts only a path recorded in a sentinel file created at session start, refuses the operator's real home, and removes the demo home and any `vantio-proof-*.html` the session recorded.
7. The F1 check fails the session when a run file in the demo home has no simulation label and is not the hostname `optics-demo.invalid` stub. It does not prove that file.
